# Multi-output Calibration Roadmap

Status: active implementation roadmap

This roadmap turns the consumer calibration design into a safe, position-specific workflow for grouped speaker rigs. It preserves the existing per-member controls (`gainDb`, positive `delayMs`, polarity, EQ, and spatial profiles) as the operational source of truth. Rig calibration receipts explain and verify those choices; they are not a second tuning store.

## Phase A: Guided perceptual calibration

- [x] Add a versioned, normalized rig-level calibration receipt with listening-position, physical-setup, level, timing, bass-integration, verification, environment, and invalidation fields. Persist it with each rig, expose it in path-hidden grouped calibration diagnostics, and cover it in the rig self-test.
- [x] Add a `Calibrate rig` entry point that presents the two supported methods: `Guided by ear` and `Measure with microphone`. Persist the chosen method with the rig calibration receipt without changing playback or tuning before route preflight.
- [x] Add route-identification preflight: confirm each member in turn and block duplicate, unavailable, fallback, or unconfirmed routes. A quiet direct signal must play before its member can be confirmed; the route receipt persists sanitized saved/resolved route facts and confirmation timestamps.
- [x] Collect a listening-position name and repeatable physical-control notes for each member before measurements begin. Require a passed route check, store a stable seat id/name plus per-member volume, bass, crossover, phase, and DSP notes, and retain a preparation timestamp.
- [x] Implement guided by-ear relative level matching with alternating pink-noise trials, randomized order, attenuation-only trim changes, and a listener confirmation. Use 1 dB corrections followed by 0.5 dB fine trials; keep changes provisional until accepted and restore them on cancel.
- [x] Implement guided by-ear arrival matching with blinded A/B timing comparisons, positive-delay-only application, and a final confirmation pass. Require accepted relative-level matching, compare shuffled A/B pulse sequences without exposing candidate values, use 5 ms then 0.5 ms comparisons, retain draft delays until a final simultaneous pulse pass is heard, and apply only the selected member's non-negative delay after explicit confirmation.
- [x] Add the optional bass/crossover stage with polarity comparison, low-band fine-delay adjustment, and an explicit hardware-control caveat. After accepted arrival alignment, let a two-member guided rig compare blinded 30-240 Hz polarity candidates and then 0.5 ms positive-delay candidates; retain both drafts until confirmation, persist the evidence, and state plainly that physical bass, crossover, phase, volume, and DSP controls remain manual.
- [x] Add music verification, a 60-second stability observation, a clear result state, and a quick re-check path. Observe only active music playback, preserve listener verdicts, snapshot live browser route stability and correction counts, report stable/correcting/may-drift/recalibration-required honestly, and provide a 15-second quick re-check after a saved result.
- [x] Ensure cancel, error, route change, and track change restore playback, routing, member mute/solo state, EQ, delay, and volume exactly. Capture a shared recovery snapshot before each guided or per-member calibration path; discard temporary direct-output media and restore captured member controls, EQ/spatial profiles, playback position/volume/rate, and the prior route on cancel or error. Abort the snapshot before a requested route or track change so the requested change can proceed cleanly. Accepted results explicitly release the snapshot instead of rolling back their intentional changes.

## Phase B: Precision microphone measurement

- [x] Replace block-envelope microphone detection with an `AudioWorklet` capture ring buffer. Capture bounded raw microphone samples with audio-render timeline frame metadata, request a transferable final snapshot after the chirp window, derive the existing pulse evidence from that buffer, and fail clearly when AudioWorklet is unavailable rather than falling back to the old 1,024-frame `ScriptProcessor` path.
- [x] Emit deterministic broadband sequences through the same per-member music graph and output sink used for playback. Inject seeded, fade-shaped broadband bursts ahead of the existing EQ, trim, spatial, limiter, and routed sink stages of the primary or confirmed secondary member graph; reject unconfirmed secondary routes instead of falling back to a hidden direct-output element, bypass only playback-time delay without changing its saved value, and record the verified graph/sink route in the microphone report.
- [x] Add sample-level measurement, A-B-B-A trials, clipping checks, repeatability statistics, residual verification, and captured microphone-processing settings. The initial coded-burst correlation path has been replaced by exponential-sweep deconvolution and first-arrival detection: the first direct arrival is selected before a louder desk, wall, or floor reflection can bias timing. The renderer captures two A-B-B-A sweep cycles through the confirmed member route, rejects clipping, low capture SNR, poor direct-to-sidelobe separation, and reflection-dominant placement, records requested/reported microphone processing, and retains median/MAD/spread, order bias, and a second-cycle residual check before any user delay is changed. Analysis runs in a Worker after capture; first-arrival placement confidence is surfaced instead of hiding a repeatable but biased result.
- [ ] Verify the corrected renderer measurement on real hardware: repeated two-speaker delay within 0.5 ms, reflection-dominant placement refused, measured polarity against an intentionally inverted cable, negotiated capture rate/time-base mapping, endpoint latency, and Worker wall time. This remains a physical gate; no release claim is made from synthetic or static checks.
- [x] Feed microphone results into the Phase A receipt while retaining the user’s final listening choice. Persist a versioned, bounded `microphoneEvidence` record only when the microphone method, passed route check, confirmed matching member, and music-graph proof all agree; expose it in the rig panel and sanitized calibration report, and refuse the attachment if normalized listener-confirmed level, arrival, bass, or music-verification receipt fields would change.

## Phase C: Long-run clock discipline

- [x] Extend the optional native mixer with endpoint-clock monitoring and bounded asynchronous resampling for follower outputs. The development-only bridge now exposes an explicitly armed two-endpoint `IAudioClock`/QPC monitoring lab, a 96-sample endpoint-clock model, a follower-only controller limited to +/-300 ppm and 20 ppm per observation, and a streaming float-PCM linear resampler that preserves fractional source position across buffers. The lab queues silence only, never claims native grouped playback is active, and cannot change routes or saved calibration values.
- [x] Keep saved acoustic alignment separate from transient runtime clock correction and merge native status into the existing sanitized rig diagnostics. A single path-hidden native-mixer status reducer now feeds the grouped rig snapshot, copyable calibration report, active speaker-system diagnostics, and J.A.M. audio-profile snapshot. `runtimeClock` is transient-only, retains bounded leader/follower ppm, ratio, buffer-fill, and clamp facts from the explicit development lab, and is covered by a rig self-test that proves it cannot change saved `delayMs`, calibration receipts, or local-path privacy. Missing, unsigned, incompatible, and bounded-lab-only bridges remain fail-closed status states rather than native playback claims.
- [ ] Complete the physical wired and Bluetooth validation matrix before making any release-quality synchronization claim.

## Guardrails

- Never send a calibration signal until the intended route is confirmed and unique.
- Automatic level matching may attenuate only; it must not boost a quieter member.
- Do not claim perfect synchronization, absolute SPL, full-room correction, or sample-locking for independent browser routes.
- Keep calibration position-specific and honest about room reflections, microphone processing, physical controls, wireless buffering, and drift.
